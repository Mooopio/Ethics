🔐 Cryptography · Lecture 4 · Exam Prep

Deep Explanation

1 · What is cryptography?
Cryptography = protection and preservation of information in all its forms. Tools evolved; the goal never changed.
  • Encryption gets by far the most attention (manipulating/protecting information).
  • Cryptanalysis = unlocking or uncovering the secrets others try to hide or obscure (the attacker/codebreaker side).
💡 Analogy: cryptography is the lock-maker; cryptanalysis is the lock-picker.
2 · History: Egyptian hieroglyphics & the Rosetta Stone
  • Intricate patterns/glyphs of hieroglyphics. Egyptians probably used them not mainly to hide secrets but to have a special writing system to commune with their gods and eternity.
  • Believed only the royal family and religious orders could fully read/write it.
  • The system grew more complex; those who could write it died or turned to other things, so the ability to decipher was lost for a time.
  • Rosetta Stone = the key that let modern civilization understand a nearly lost language; it took over 20 years of concerted effort.
⚠️ Trap: hieroglyphics were NOT primarily designed as a secrecy system.
3 · Evolution: from protecting to also detecting

A major use of cryptography is safeguarding communication between two parties sharing information. Today information must be kept secret and unwelcome modifications must be detectable. In its first generations cryptography only protected information; that has changed.

4 · The five goals (C-I-A-N-K)

5 · How it works: the vocabulary
Plain/clear text: the original, unaltered, usable message.
Cipher text: plain text transformed to another format by an algorithm; reversible using an algorithm and a key.
Algorithm: a formula of discrete steps describing how encryption and decryption are performed.
Key: a discrete piece of information, usually random, that determines the output of a cryptographic operation.
💡 Analogy: plain text = letter; algorithm = the type of safe; key = the combination; cipher text = letter locked inside.

Flow: Plain text → [algorithm + key] → Cipher text → [algorithm + key] → Plain text.

6 · Symmetric cryptography

The same key encrypts and decrypts and must be kept secret.

Strengths: confidentiality; increased speed over many non-symmetric systems; simplicity (relatively); authenticity.
Drawbacks: key management issues; no nonrepudiation.

💡 Analogy: one house key copied for everyone. Fast and easy, but you must hand copies out safely, and nobody can prove which copy-holder opened the door.
7 · Asymmetric (public-key) cryptography
  • Invented to overcome the key management problems of earlier systems.
  • Each enrolled user gets a key pair: public key (published) and private key (secret).
  • No shared symmetric key is needed, so it protects against eavesdropping or betrayal.
  • Provides nonrepudiation, impossible with symmetric systems.
💡 Analogy: a public mailbox slot (anyone can drop in) that only you can open with your private key.
8 · Digital signatures

Anything encrypted with the private key can be reversed only with the matching public key. Only one person holds the private key, so the identity of the encrypting party is assured.

9 · Hashing
  • A type of one-way “encryption”: scrambled output that cannot be reversed. Output = hash / hash value / message digest.
  • Used to validate integrity; also password storage.
  • Fixed-length output regardless of input size.
  • Value is unique for each different input, so any change in data of any type is detected.
💡 Analogy: a fingerprint of a document. Fingerprint can’t rebuild the person, but a different person gives a different print.
10 · Issues: brute-force attack

All cryptographic systems are vulnerable to brute force: every possible combination of characters is tried to find a valid key.

Smart Summary

  • Cryptography = protect & preserve information · Cryptanalysis = break/uncover secrets
  • History: hieroglyphics (gods/eternity, not secrecy; royals & priests) → knowledge lost → Rosetta Stone (20+ years)
  • Goals: Confidentiality · Integrity · Authentication · Nonrepudiation · Key distribution
  • Terms: plain text → (algorithm + key) → cipher text
  • Symmetric: one secret key · fast, simple · ✗ key management, ✗ nonrepudiation
  • Asymmetric: public + private pair · fixes key management · ✓ nonrepudiation
  • Digital signature: private key encrypts → public key verifies → identity assured
  • Hash: one-way · fixed length · integrity · passwords
  • Weakness: brute force (try every key)

Common mistakes & traps
Saying hieroglyphics were made to hide secrets (they were for communing with gods).
Saying hashing can be decrypted (it can’t).
Confusing public/private roles: the signature uses the private key.
Listing speed as a symmetric drawback (it’s a strength).
Forgetting nonrepudiation is the symmetric weakness that asymmetric fixes.
